# Release note — импорт выписки 1.0.0

Фрагмент приложения: выбор PDF/CSV-выписки, проверка на устройстве, отправка байтов на сервер, ожидание отчёта о регулярных списаниях, удаление импорта. Сборка — Expo SDK 58, React Native 0.88.

## Проверено

| Платформа | Где | Результат |
| --- | --- | --- |
| iOS | iPhone 17 Pro Simulator (iOS 26.5), Xcode 27.1 | Development build. Пройдена вся матрица приёмки, тёмная тема, крупный системный шрифт |
| Android | Android Emulator Pixel Fold (Android 15, API 35) | Development build. Пройдена та же матрица приёмки, что на iOS: happy (CSV и PDF), lost_ack с перезапуском, stale_status, delete_failure → повтор → удалено, spoofed и oversize, работа без сервера. Поведение, тексты и счётчики mock — как на iOS |

Физические устройства и release-сборки не проверялись.

## Разрешения

Пользователь не увидит ни одного системного запроса разрешений.

- **Файлы.** Разрешения на хранилище не нужны: файл выбирается через системный picker (iOS — `UIDocumentPicker`, Android — Storage Access Framework), и приложение получает доступ только к выбранному файлу. Разрешения `READ/WRITE_EXTERNAL_STORAGE`, которые добавляет `expo-file-system`, вырезаны из Android-манифеста (`android.blockedPermissions` в `app.json`).
- **Android, release-сборка** (проверено по итоговому манифесту): `INTERNET` — сеть; `ACCESS_NETWORK_STATE` и `ACCESS_WIFI_STATE` — NetInfo узнаёт, есть ли сеть; `VIBRATE` — тактильный отклик. Все они обычные, без запроса. Ещё `…DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` — внутреннее разрешение AndroidX, доступное только самому приложению.
- **Вырезано** через `android.blockedPermissions`: `SYSTEM_ALERT_WINDOW` (остаётся только в debug-сборке, для dev-меню React Native) и `USE_BIOMETRIC`/`USE_FINGERPRINT`, которые добавляет `expo-secure-store` (вход по биометрии не используется).
- **iOS:** запросов нет. `NSLocalNetworkUsageDescription` нужна только dev launcher; из release-сборки её убирает его же скрипт сборки.

## Где остаются данные

| Что | Где | Когда удаляется |
| --- | --- | --- |
| Копия выбранного файла | iOS: `Library/Caches/statement-imports/<id>`; Android: `cacheDir/statement-imports/<id>`. Имя — случайный id, без исходного имени. Caches не попадает в бэкапы | Сразу после ответа сервера на отправку (принят или отклонён), при отмене и при выборе другого файла. Если приложение убили раньше, лишние копии удаляются при следующем запуске |
| Временная копия picker'а (iOS, `tmp/…-Inbox`) | Переносится в папку выше, а не копируется | Не остаётся |
| Запись операции: ключи, jobId, ревизия, размер, формат | iOS Keychain / Android Keystore через `expo-secure-store`, режим `AFTER_FIRST_UNLOCK_THIS_DEVICE_ONLY` — не синхронизируется в iCloud и не переносится на другое устройство. Доступна после первой разблокировки, чтобы ответ сервера, пришедший на заблокированный телефон, тоже записался | После подтверждённого удаления или окончательной ошибки; при «Новый импорт»/«Отмена»; при первом запуске после переустановки. Если приложение удалили посреди импорта, на iOS запись остаётся в Keychain до повторной установки, см. ниже |
| Имя файла, хеш, отчёт (мерчанты, суммы) | Только память процесса | При закрытии приложения. После перезапуска отчёт заново приходит с сервера |
| Логи | Только события и id (белый список полей), без имени файла, байтов, ключей и сумм. В release консольный вывод отключён | — |

Android-бэкапы выключены (`allowBackup: false`).

**Как очистить данные.**
- Надёжнее всего удалить импорт в приложении: сервер подтвердит `deleted`, и запись удалится.
- **Android:** удаление приложения или «Настройки › Приложения › Хранилище › Очистить данные» стирает всё.
- **iOS:** удаление приложения стирает копию файла. Запись в Keychain система при удалении не трогает (так устроен iOS: приложение не узнаёт, что его удаляют). Это касается любого приложения, которое хранит данные в Keychain, в том числе банковских. Стирать такие записи при первом запуске после установки — обычный приём, так сделано и здесь. Но запись есть только у незаконченного импорта: после подтверждённого удаления на сервере, окончательной ошибки, «Новый импорт» или «Отмена» её уже нет. Если удалить приложение посреди импорта, в Keychain останутся ключи, jobId, ревизия, размер и формат, без имени файла и данных выписки. Читать её может только это приложение на этом устройстве, в бэкапы она не попадает, а при первом запуске после повторной установки стирается.

## Что остановит rollout

Аналитика в этот фрагмент не подключена. Ниже — сигналы, которые стоит собирать (события журнала уже без персональных данных) и при которых раскатку останавливают:

- **Второй job на одну операцию:** больше одного `jobId` на один ключ операции или рост `duplicateHits` выше обычного. Это стоп-фактор: дубликат импорта.
- **«Удалено» без подтверждения:** любое `deleted` без предшествующего `GET … deleted`. В коде это запрещено машиной состояний, но сигнал нужен как страховка.
- **Растёт доля «застрявших» операций:** `unknown` или `not_received` дольше нескольких минут, а также `delete_failed`.
- **Растёт `copy_lost`:** система чистит Caches раньше, чем файл уходит. Это первый кандидат на поломку при агрессивной очистке памяти.
- **Ответы, не совпадающие с контрактом:** растёт `ProtocolError`.
- **Не пишется хранилище:** событие `store_failed`. Если запись не удалась перед отправкой, файл не уходит: без сохранённого ключа повтор мог бы создать второй job. Пользователь видит «Не удалось сохранить на устройстве» и может нажать ещё раз.
- **Падения при запуске после обновления.** Например, если запись операции старого формата не читается.

## OTA или новый бинарник

OTA-обновления (`expo-updates` / EAS Update) в проект не подключены. Сейчас любое изменение доставляется только новой сборкой. Если их подключить, граница такая.

**Можно через OTA (JS-бандл):**
- тексты и экраны;
- машина состояний, таймауты и интервалы опроса;
- правила проверки файла;
- формат записи операции, но только с обратной совместимостью: старая запись должна читаться;
- экран диагностики.

**Нужен новый бинарник:**
- добавление, удаление или обновление нативных модулей (`expo-secure-store`, NetInfo, Reanimated/Worklets, `expo-file-system`, document picker), смена Expo SDK;
- всё в `app.json`, что превращается в нативную конфигурацию: разрешения, `blockedPermissions`, `allowBackup`, плагины, bundle id, иконки;
- сетевые настройки: ATS на iOS, cleartext-трафик на Android, адрес сервера на другом домене с другой политикой безопасности.

**Важно для боевой сборки.** Mock работает по `http://127.0.0.1`. В release-сборке iOS (ATS) и Android (cleartext выключен) разрешают такие адреса только локально, поэтому боевой сервер должен быть на HTTPS. Адрес задаётся при сборке через `EXPO_PUBLIC_API_URL`.

## Известные ограничения

- Если ОС удалила копию файла до повторной отправки, пользователь видит «Файл нужно выбрать заново». Автоматической сверки выбранного заново файла с первоначальным (по хешу) нет.
- Отчёт не хранится на устройстве — это сделано намеренно, ради безопасности: суммы и названия мерчантов не попадают на диск. Поэтому после перезапуска без сети пользователь видит «Загружаем отчёт», пока связь не появится. При надобности это спокойно меняется. Достаточно не обнулять отчёт в `save()` в [src/core/store.ts](src/core/store.ts) (то же для имени файла), и всё будет храниться в той же зашифрованной записи в Keychain. Это изменение JS, его можно доставить без нового бинарника.

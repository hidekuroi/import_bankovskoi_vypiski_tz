# Импорт банковской выписки — тестовое задание Mobile Engineer

React Native 0.88 + TypeScript, Expo SDK 58 (development build, не Expo Go), Expo Router.
Набор кандидата лежит в [`kit/`](kit) без изменений (проверка — [в конце](#кит-не-изменён)); всё остальное — мобильный клиент.

Release note — [RELEASE_NOTES.md](RELEASE_NOTES.md), self-review — [SELF_REVIEW.md](SELF_REVIEW.md).

## Запуск

Для всего нужен Node 24 (`.nvmrc`). Дальше — по платформе:

- **iOS** — только macOS: Xcode 26+ с iOS Simulator и CocoaPods.
- **Android** — macOS, Windows или Linux: Android Studio с эмулятором и JDK 17. Путь к SDK берётся из `ANDROID_HOME`, а если переменной нет — из стандартной папки Android Studio.

```bash
nvm use            # или любой другой способ поставить Node 24
npm ci
npm run ios        # первый раз: собрать dev client, поставить на симулятор, поднять mock и Metro
npm run android    # то же для запущенного Android-эмулятора или устройства по USB
```

Дальше хватает одной команды:

```bash
npm start          # mock кита + Metro для уже установленной сборки
```

Что делает `npm start` ([scripts/dev.mjs](scripts/dev.mjs)):

- запускает mock кита ровно как его собственный `npm start`: `http://127.0.0.1:8787`;
- создаёт `oversize.csv` командой кита;
- кладёт тестовые файлы туда, где их увидит системный picker;
- для Android делает `adb reverse`;
- запускает Expo.

Ctrl+C останавливает всё сразу.

Если Metro занял не порт 8081 (порт был занят), откройте приложение в dev launcher на том порту, который напечатан в консоли.

**На своём телефоне.** Телефон и Mac должны быть в одной Wi-Fi-сети.

```bash
npm run ios -- --device      # выбрать подключённый iPhone; для Android: npm run android -- --device
npm start -- --lan           # когда сборка уже стоит на телефоне
```

С этими флагами mock открывается в локальную сеть, а приложение ходит к нему по адресу Mac, а не по `127.0.0.1`: на телефоне это адрес самого телефона. Для iPhone нужны:
- кабель и «Доверять этому компьютеру»;
- включённый «Режим разработчика» (Настройки › Конфиденциальность и безопасность);
- команда подписи в Xcode (подойдёт бесплатный Apple ID).

При первом запуске разрешите доступ к локальной сети. Тестовые файлы на телефон нужно перенести самим, например через AirDrop в «Файлы».

Тестовые файлы в системном picker:
- iOS — «Файлы › На iPhone › Statement fixtures»;
- Android — `Download/Statement fixtures`.

Если папки нет, выполните `npm run fixtures` при запущенном симуляторе или эмуляторе.

## Как пользоваться приложением

Внизу две вкладки: **Импорт** и **Диагностика**. Диагностика есть только в dev-сборке. На iOS и Android всё работает одинаково.

1. **Выбрать файл.** Открывается системный picker. Приложение копирует файл к себе и проверяет его до отправки:
   - размер — не больше 10 МБ;
   - первые байты — `%PDF-` или строка `date,description,amount`.

   Если файл не подошёл (`spoofed.pdf`, `oversize.csv`), появится «Файл не подходит… На сервер ничего не отправлено».
2. **Проверить и отправить.** Экран подтверждения показывает имя, размер и формат. Файл уходит на сервер только по кнопке «Отправить».
3. **Следить за статусом.** Шаги: «Отправка на сервер → В очереди → Обработка → Отчёт готов». Статус обновляется сам, без индикатора загрузки. Потяните экран вниз, чтобы спросить сервер сразу: индикатор появляется только в этом случае.
4. **Отчёт.** Показывает итог 151,99 AUD в месяц и два списания. «Подробнее» открывает карточку списания.
5. **Удалить импорт.** Кнопка есть с момента, когда сервер принял файл, даже если отчёт ещё не готов. Если сервер больше минуты держит импорт в очереди или обработке, экран пишет «Обработка идёт дольше обычного». Сначала «Удаляем…», и только после подтверждения сервера — «Удалено на сервере». Если сервер ответил ошибкой: «Не удалось удалить, данные по-прежнему на сервере» и кнопка «Повторить удаление».

**Если ответ на отправку не пришёл,** экран пишет «Неизвестно, дошёл ли файл». Приложение само проверяет это по ключу операции, а кнопка «Проверить» делает то же вручную. Если импорт по ключу не найден, можно отправить файл повторно: ключ тот же, дубликата не будет.

**Без связи** сверху появляется плашка «Нет сети» или «Сервер не отвечает». Её можно смахнуть вверх, а сама она уходит, когда связь вернулась. Приложение в это время только переспрашивает сервер и ничего не отправляет заново. Проверить на симуляторе проще всего, остановив mock: `npm run mock` запускает его снова.

**Перезапуск в любой момент безопасен.** Приложение помнит операцию и после запуска сверяется с сервером, но файл само не отправляет.

## Экран диагностики

| Блок | Что там |
| --- | --- |
| Mock | Адрес; переключатель сценариев (`happy`, `lost_ack`, `stale_status`, `delete_failure`); живые счётчики `GET /__test/state`; список job'ов с sha256 |
| stale_status: запрашивать статус автоматически | Включено по умолчанию: при `stale_status` и готовом отчёте приложение само повторяет запрос статуса, пока не придёт устаревший ответ. Выключено: потяните экран «Импорт» вниз дважды |
| Приложение | Фаза операции и job; что лежит в Keychain (есть ли ключ удаления, нет ли там имени и хеша файла); есть ли локальная копия; совпадают ли sha256 отправленных байтов и байтов на сервере |
| Сразу проверять по ключу после потери ответа | Включено по умолчанию. Выключите, чтобы проверить lost_ack с перезапуском: проверка по ключу пройдёт при следующем запуске |
| Сбросить mock и приложение | Чистит состояние mock и операцию в приложении |
| Журнал | События приложения без данных выписки: например, `snapshot_ignored … ignored=stale` |

## Матрица приёмки

| Сценарий | Действия | Что должно быть видно |
| --- | --- | --- |
| happy | Выбрать `statement.csv` или `statement.pdf` → «Отправить» | Шаги до «Отчёт готов»; 2 списания, 151,99 AUD в месяц; `newJobs` +1 |
| lost_ack | Диагностика: `lost_ack` → новый импорт → «Отправить» | «Неизвестно, дошёл ли файл» → проверка по ключу находит тот же job; `newJobs` +1, `duplicateHits` 0 |
| lost_ack + relaunch | Выключить «Сразу проверять по ключу», отправить, закрыть приложение, открыть | При запуске проверка по ключу находит job, повторной отправки нет |
| stale_status | При готовом отчёте выбрать `stale_status` | Экран остаётся «готово, ревизия 3»; в журнале `snapshot_ignored status=processing revision=2 ignored=stale` |
| delete_failure | `delete_failure` → «Удалить импорт» → `happy` → «Повторить удаление» | «Не удалось удалить…»; после повтора с тем же ключом — «Удаляем…», затем «Удалено на сервере» |
| spoofed + oversize | Выбрать `spoofed.pdf`, затем `oversize.csv` | «Файл не подходит»; `createRequests` не меняется |

## Тесты

```bash
npm test           # клиент против настоящего mock кита (Node ≥ 22.18)
npm run test:kit   # тесты самого кита
npm run verify     # типы + линтер + оба набора тестов
```

Тесты гоняют тот же код импорта, что и приложение. Запросы идут по HTTP к `createMockServer` из кита: на порту 0, с временным состоянием, поэтому результаты воспроизводимы.

- [tests/matrix.test.ts](tests/matrix.test.ts) — матрица приёмки со сверкой счётчиков mock:
  - ключ сохранён до POST;
  - один job при lost_ack (и после перезапуска);
  - устаревшая ревизия не откатывает экран;
  - 503 на удалении и повтор с тем же ключом;
  - spoofed и oversize отклоняются без единого запроса.
- [tests/faults.test.ts](tests/faults.test.ts) — отказы сети, подменённые на стороне клиента:
  - 503 → проверка по ключу → повтор;
  - сервер пропал и вернулся;
  - приложение убито во время DELETE;
  - удаление импорта, который ещё в очереди;
  - 404 на DELETE;
  - поздний ответ после удаления;
  - что попадает в хранилище;
  - хранилище отказало в записи: до отправки файл не уходит, после — импорт продолжается.
- [tests/units.test.ts](tests/units.test.ts) — проверка файла, разбор ответов, деньги, тексты экрана, хаптики, логгер.

Последний прогон `npm run verify`: типы и линтер без ошибок, 48 тестов клиента и 6 тестов кита прошли.

Во всех наборах проверяется, что в логах нет имени файла, байтов и данных выписки. Тестам нужен Node ≥ 22.18 (они запускают TypeScript без сборки); сам кит работает на Node 20+.

## Устройство

```
src/core/          ядро без React Native: проверка файла, HTTP-контракт, машина состояний, движок, логгер, хранилище
src/platform/      expo-file-system, expo/fetch + File.upload, Keychain (expo-secure-store), NetInfo, picker
src/presentation/  какие тексты, шаги и хаптики показывать в каждом состоянии
src/app/           экраны: вкладки «Импорт» и «Диагностика», лист с карточкой списания
tests/             node:test против mock кита
kit/               набор кандидата без изменений
```

Ключевые решения:

- **Сначала запись, потом запрос.** Ключ операции сохраняется до POST, ключ удаления — до DELETE. Все повторы идут с теми же ключами.
- **Нет ответа — значит «неизвестно», а не «ошибка».** Приложение спрашивает `GET /imports/by-key/{key}`. После перезапуска — только проверка, повторная отправка только по кнопке.
- **Ревизии только растут.** Устаревший ответ не применяется. После запроса на удаление принимаются только `deleting` и `deleted`, а «удалено» — только по GET.
- **Файл проверяется по содержимому**, а не по расширению или MIME. Одна приватная копия лежит в Caches и удаляется, как только сервер получил байты. Загрузка идёт нативным стримом, файл не читается в JS.
- **На устройстве минимум.** В Keychain хранятся только ключи, jobId, ревизия, размер и формат. Имени файла, хеша и отчёта на диске нет. Подробнее — в [RELEASE_NOTES.md](RELEASE_NOTES.md).
